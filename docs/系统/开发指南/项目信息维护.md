# 项目信息维护方法

本文件维护信息分工、记录流转和阶段收尾方法。项目导航见[项目信息管理](../../../项目信息管理.md)，具体项目仍遵循自身规范、最新用户指示与实际实现。

## 一处正文，各入口引用

| 信息 | 维护来源 | 其他位置如何使用 |
|---|---|---|
| 当前有效的业务规则和实现方法 | docs中的对应主题 | 链接规则，不复制整套定义 |
| 用户原始输入、会议原件和参考材料 | 本机记录/资料或指定原稿位置 | 保留原意，记录引用来源 |
| 实际环境、凭据和配置 | 本机记录/资源的唯一维护位置 | 只引用位置、环境和加载方式 |
| 已交付状态、最近核对及当前问题 | 当前进度.md | 交接和计划引用，不再维护一份台账 |
| 尚未完成的工作、验收和待确认事项 | 工作计划.md | 完成后移出待办，结果引用项目记录 |
| 当前任务、停点、约束和接续动作 | 当前交接.md | 固定入口持续更新，不与日期快照绑定 |
| 稳定背景和定位线索 | 项目上下文.md | 不保存临时分支、PID或待发布状态 |
| 实际过程、重要失败和验证证据 | 按实际日期的项目记录 | 详细结果只保存一次 |
| 值得追溯的关键决定和阶段结果 | 按需保存的日期或主题摘要 | 引用项目记录，不再抄全文 |
| 文件与主题导航 | 本机总索引及资料、资源、项目记录各自的固定索引 | 上级只链接下级，不重复维护同范围清单 |
| AI接续与历史摘要导航 | AI阅读入口及AI交接历史索引 | 当前接续和历史追溯分开，项目事件转到项目记录索引 |

说明当前行为时核对代码、契约、配置和必要数据；记录中的计划、旧版本和成功结果不能单独证明现状。开发、提交、合并、部署和业务验收分别记录。

## 日常更新

1. 处理用户任务并核对实际结果，区分原话、已确认结论、建议与未知事项。
2. 长期结论更新对应docs；环境事实更新资源；交付状态更新当前进度，未完成事项更新计划。
3. 发生有价值的决定、阶段结果、失败排查、发布或交接时，集中更新同主题项目记录；普通问答、工具调用和重复检查不另建记录。
4. 当前交接直接维护接续所需信息。只有独立留档价值明确时才保存日期摘要，无需先建立日期副本再复制回当前交接。
5. 新增、改名、移动、合并或删除重要文件时，更新所属固定索引和已知入链。项目事件进入项目记录索引，AI阶段摘要进入AI历史索引；仅修改正文时无需另建索引或复制摘要。

当前交接应短，读完能知道任务、停点、必须保留的内容和下一步。复杂过程链接到工作文件或项目记录，不把交接写成完整项目文档。

## 固定索引与目录导航

长期积累的信息应当有稳定入口，但不要求每个文件夹都建立索引。索引放在其导航范围的外层，与下一级日期或主题文件夹同层持续维护；过程记录仍按事件日期保存。

| 位置 | 索引职责 | 维护边界 |
|---|---|---|
| 本机记录/本机记录索引.md | 总导航，按问题进入资料、资源、状态和历史 | 不重复下级文件清单 |
| 本机记录/资料/资料索引.md | 阶段、模块、专题、原稿与交付包 | 不把参考建议写成已确认规则，不改写原件 |
| 本机记录/资源/资源索引.md | 资源说明和实际配置维护位置 | 不复制账号、密码、Token和连接串 |
| 本机记录/记录/项目记录/项目记录索引.md | 项目事件的主题与日期入口 | 不按天新建，不把历史状态当作当前状态 |
| 本机记录/记录/AI记录/阅读入口.md | 接续当前任务的最短阅读路线 | 复用既有入口，不再另建AI总索引 |
| 本机记录/记录/AI记录/会话交接/历史索引.md | 值得保留的AI阶段摘要及缺失原稿说明 | 项目事件目录链接到项目记录索引，不平行维护 |

**是否需要独立索引**：文件持续增长、跨日期难查、跨主题引用较多，或已有入口离使用位置太远时建立。少量文件能由上级直接说明的目录不单独建立；工作目录直接维护当前进度和工作计划。模板预置常用四份固定索引，空白部分在产生真实资料后填写，不机械复制业务阶段或每天的目录。

**索引条目**：一般只写主题或文件名、一句话用途和相对链接。需要时标注原事件日期、资料性质或适用范围。项目事件可同时提供主题和日期两种查找方式，但正文始终只有一处；不在多个索引重复维护一份完整事件清单。

**规模与附件**：项目记录优先收录日期直属的过程正文和关键证据入口，不逐条展开截图、日志、发布包、缓存或归档内部文件。原始资料包优先引用包入口。索引较长时先在同一文件内按主题、月份组织；确需拆分时按稳定专题划分，上级保留导航，不演变成每日索引。

**现有索引衔接**：先比较覆盖范围，再移动或合并导航条目。旧入口已有入链时保留清楚的跳转；移动链接时按新位置重算相对路径，检查锚点。AI历史索引已有项目事件时，将事件导航集中到项目记录索引，原摘要、原件及有效证据保持。

**目录规则**：分类层以文件夹为主，必要的固定索引作为导航入口保留在外层，正文归内容层。不为每层添加README；项目和实际工程根README继续承担原有工程入口职责。

**维护时机**：新增长期主题、关键记录或资源说明，以及文件改名、移动、合并、删除时同步所属索引。普通问答、工具调用、正文微调不产生新的索引文件或日期快照。维护者按任务更新真实条目，不预造发布、验收、账号或链接。

## 同主题记录与日期

同日同主题优先一份过程正文，补充新增的有效信息。实施中、待发布、已发布等阶段可在同一记录中按实际事件时间说明，不为每次状态变化复制完整说明。

同一主题跨日推进时保留各事件的实际日期及相应证据，归整日期单独标注。不要按文件移动时间重定事件日期，也不能将旧阶段全部改写为最新状态。日期摘要可汇总同日相关主题；主题摘要可串联跨日决定，按实际查询需要选择，不固定每个项目的数量、篇幅或归并粒度。

## 收尾与冗余整理

- 先盘点正文、引用、附件和维护来源，判断哪些是重复说明、已被替代的AI摘要、独有证据或仍未解决的事项。
- 将有效结论、重要失败、必要验证、未完成事项和来源分别保留到其维护位置。已完成事项从工作计划移出，现行规则直接更新，不叠加多个失效版本。
- 确认同主题信息已覆盖后，合并重复摘要。日常入口只列简洁摘要和证据链接，完整日志、截图、逐字历史及恢复材料按需查看。
- 需要回退整理或存在保留价值不确定的内容时，可先保存一次有明确用途的快照、原路径清单和合并映射。能够可恢复归档时优先保持原文；是否删除依据内容价值及已授权范围，不能只看日期早晚或任务是否结束。
- 用户原始笔记、需求原话、会议资料和参考材料保持原意；混合文档只调整明确允许维护的部分。维护权限或保留价值不清楚时保留并说明，不凭文件名或目录猜测。
- 配置、凭据、业务数据、发布包和备份不属于普通记录清理。不要因为文档整理执行数据库、生产、模型或外部消息操作。

迁入附件的原文仍描述原路径和当时状态；可保留原文不改，但需说明恢复路径，并为日常摘要建立有效引用。原文归档与现行导航分开，归档不默认进入后续AI上下文。

## 整理验证

| 检查 | 要确认什么 |
|---|---|
| 内容与归属 | 一项当前信息有明确维护来源；摘要不丢关键决定、失败或未完成事项 |
| 日期与状态 | 原事件日期保持，归整日期另列；不把技术检查当业务验收 |
| 引用与索引 | 所属索引和已知入链已更新，相对链接及锚点有效；缺失证据如实标明 |
| 模板边界 | 目录树和实际文件一致；业务栏目留空，资源空文件不带真实值，不把项目记录复制成通用模板 |
| 文件 | UTF-8可读、代码围栏成对，移动目标不覆盖其他资料 |
| 原文保全 | 采用快照或归档时核对文件清单及可恢复性，不为业务内容额外建立哈希体系 |
| 私有边界 | 本机记录排除Git、构建、镜像、发布包及同步；模板和分发资产不含真实项目值 |

没有原稿、未执行或失败的验证应保留真实说明，不能重建伪证据。归档副本允许保留历史相对路径时明确标注，日常导航按实际位置验证；不能以此豁免现行入口的断链。

## 套用已有项目

先核对现有结构与项目规范，只创建缺失入口，同名文件比较后合并明确需要的内容。占位文件表示未初始化，不代表已有实现或任务结束。模板中日期目录和主题文件为命名示意，使用时替换为实际事件；不预造真实日期、发布或验收结果。

资料管理方式的更新不自动重组所有项目。复制目标项目的必要规范时保留原有维护来源、仓库边界、职责与授权，不把本模板作为新增生产操作权限。
