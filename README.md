# 项目信息管理模板 · 第五版

项目仓库：[sude-weixiao/WX-PIM](https://github.com/sude-weixiao/WX-PIM)。

本仓库跟踪可复用的空白模板资产，其中本机记录目录仅保存索引、填写骨架和空资源文件。复制到实际项目后，整个本机记录目录须排除Git、镜像、构建、发布包和同步；实际项目资料、凭据及工作状态不回填本仓库。

本目录是可复制的主模板。固定索引放在主题或日期文件夹外，持续维护；当前规则、工作状态、原始资料和历史证据分别保存，每项正文只维护一处；具体维护和收尾方法统一见[项目信息维护](docs/系统/开发指南/项目信息维护.md)。

负责人查看资料与工作状态，AI根据已确认需求、实际实现及证据维护内容。新信息优先进入已有分类，不因每次任务新增一级目录。

目标项目的导航骨架见[项目信息管理](项目信息管理.md)，本机入口见[本机记录索引](本机记录/本机记录索引.md)。

分类层以文件夹为主，允许必要的固定索引放在外层；正文放内容层，不逐层建立README，也不按日期新建索引。AI记录的固定入口与会话交接目录采用上图布局。项目日期内容目录可保存正文和对应附件，分类目录不散放截图或日志。模板根README承担使用入口职责。

资料少时直接放文件，确需分类时按实际主题扩展；具体模块优先归入既有系统类别。改变层级时将同层内容一起合理归类并更新引用，不为统一外观重构项目仓库。

## 内容分工

- 业务背景、功能流程、公共规则和验收标准分别维护；公共规则只保留一份正文，各功能引用。
- 架构设计管理分层和依赖，接口对接管理契约与调用，开发指南管理可复用开发测试方法，部署运维管理运行与恢复方法。
- 数据表清单链接单表说明，功能映射只写具体读写用途，不复制字段定义。多库或schema按实际规模分组；真实结构、模型和迁移不一致时如实标记。关系通过字段及业务逻辑维护，不创建物理外键，已有外键不在资料整理时擅自删除。
- 资料保存用户原文与输入，整理稿和建议明确区分；确认结论进入docs，安排进入工作，处理证据进入记录。
- 资源按服务器、数据库、平台服务和开发环境分类，同一资源的地址、凭据、配置及加载方式集中维护。已有公司级来源或实际配置时引用，不能另抄一套密码。资源文件名或章节注明环境。
- 进度记录当前交付，计划只保留未完成事项；交接说明当前停点，稳定上下文只负责背景和定位。详细操作和验证引用项目记录。
- 历史只按需查看；同主题阶段事实集中记录，摘要按日期或主题收拢，不固定每个项目的摘要数量。

## 套用方式

1. 复制所需docs、本机记录及项目信息管理.md到目标项目，只补缺失文件。同名正文先比较、保留用户内容，不整目录覆盖。
2. 本README是模板使用说明，不覆盖目标项目根README；在目标项目README补入项目信息管理.md的链接即可。前后端分仓库继续沿用原布局，整体说明选定一处，本机资料可集中在共同父目录。
3. 资源四份空Markdown是有意预留；四份固定索引及其他文件是无业务内容的填写骨架，实际位置见下表。按事实填写，未核验部分保留未知，删除不适用占位，不猜测实现或预造结果。
4. 日期目录可参考[项目记录占位目录](本机记录/记录/项目记录/YYYY-MM-DD/)；主题正文按[记录模板](本机记录/资源/开发环境/记录模板.md)填写，必要阶段摘要按[摘要模板](本机记录/资源/开发环境/阶段摘要模板.md)填写。无需为普通问答或每次交接创建日期副本。
5. 本机记录排除Git、镜像、构建、发布包和同步。位于仓库根时可用/本机记录/忽略规则；其他位置按实际路径配置，并检查已跟踪文件。

真实项目的密码、Token、私钥、连接串、现场数据和部署状态不回填本模板或分发资产。资料整理不改变配置加载，也不构成生产或外部操作授权。

## 合入项目规范

将下列要点与目标项目AGENTS.md或同等规范合并，保留既有职责和授权：

```markdown
- 项目信息使用既定分类，当前规则、当前状态、原始资料和过程证据分别维护；每项正文有一个明确来源。
- docs保存当前有效的业务和系统知识；本机记录按资料、资源、工作、记录组织，凭据和配置集中维护。
- 当前进度持续更新交付状态，工作计划仅保留未完成事项；实际过程按事件日期保存于项目记录。
- 本机记录使用固定总索引及资料、资源、项目记录索引；必要索引放在日期或主题文件夹外持续维护，不按天创建、不逐层重复。
- 新增或移动重要文档时同步所属索引。项目事件导航由项目记录索引集中维护，AI历史索引只管理阶段摘要及缺失来源；上级入口链接下级，不复制同范围清单。
- 新会话或压缩后先读固定当前交接，再按需补查上下文和历史；不默认通读全部记录。
- 当前交接直接持续维护，无需每次先存日期快照；有独立留档价值时保存阶段摘要，同日同主题集中新增有效信息。
- 阶段结束保留有效结论、未完成事项、重要失败和必要证据，再归并重复AI摘要，更新索引与引用。
- 原事件日期与归整日期分开，历史不作为当前授权；原稿、资源配置、业务数据、发布包和备份不属于普通记录清理。
- 验证现行链接、编码、归档去向和保留边界，技术验证、提交、发布与业务验收分别报告。
```

完整流程和收尾判据只维护在[项目信息维护](docs/系统/开发指南/项目信息维护.md)。[阅读入口](本机记录/记录/AI记录/阅读入口.md)为按需查找路线；模板初始状态不代表具体项目完成，也不要求停止已经明确的任务。
